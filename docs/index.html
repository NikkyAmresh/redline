Plans in the terminal

A wall of text and one accept or reject. Your feedback gets typed from memory ("in step 4...") and scrolls away.

Prototypes in chat

You see the problem in a second, then spend minutes describing where it is to an agent that cannot see your screen.

Redline moves both into the browser, where every note points at an exact place, and sends them back to the session in one batch.

Plans

Review a plan like a doc, not a diff.

Claude writes the plan as a markdown file and opens it as a real document: mermaid diagrams, tables and phase checklists, versioned per project.

  • Comment or suggest an editSelect any sentence and press C or E. Attach screenshots. Drafts collect until you send them.
  • Notes point at one exact placeEach comment records its source lines and offsets, plus a path like Phase 2 › item 2. The markdown stays untouched.
  • Questions come back in redWhen Claude needs a decision, it opens a "Needs your reply" thread on the exact passage. Reply right there.
  • Every version keptSee what changed since the last version, open any past one, restore it or download it as .md.

Prototypes

Pin feedback to the component, not a screenshot.

Ask for a prototype and Claude builds a playable dummy of any app or website: real screens, fake data, every button does something. You review it by using it.

  • Press C and click itComment mode outlines whatever you point at. Click to pin a note to that component; hold Alt for the exact element.
  • Suggest the exact wordsOn any text, switch to Suggest copy and type the replacement for a button, heading or label.
  • Box a whole areaDrag a box over a section when the note is about layout, not one element.
  • It sees what you sawEvery pin records the screen, the component id and a screenshot, so Claude never has to guess.

How it works

One loop for plans and prototypes.

Your feedback lands back in the session that made the work, without breaking what it was doing.

  1. Claude makes itIt writes the plan or builds the prototype, commits v1 and opens it in your browser.
  2. You reviewSelect a sentence, or press C and click a component. Drafts pile up quietly.
  3. Send to ClaudeOne batch, one click. A signal lands in inbox/.
  4. The session picks it upWithout dropping its work. Or switch on Run independently and a background agent takes it.
  5. The page updates liveThe next version arrives, resolved notes turn green, open questions come back in red.

Your work never leaves your machine

The server binds 127.0.0.1, rejects foreign Host headers and never phones home. Plans, prototypes, feedback and screenshots live in ~/.claude/redline as plain files, with a git history of every version. It is a single reviewer tool on purpose; don't put it on the internet.

Small on purpose

  • One Python stdlib file, no dependencies, marked and mermaid vendored
  • Plans and prototypes survive /clear, compaction and restarts
  • Checkboxes tick while Claude implements, so a plan doubles as a progress board
  • Starts with each Claude Code session, one server for all of them
  • MIT licensed, yours to bend
Quick start

Two commands in Claude Code.

>/plugin marketplace add NikkyAmresh/claude-plugins
>/plugin install redline@nikkyamresh # starts with each session

Then ask any session for a plan or a prototype, or run /redline:plan-review or /redline:prototype-review. Two demos ship with it, a plan and the playable app it describes, so you can try the loop right away. Python 3.7+ and Claude Code, on macOS or Linux. Your plans live in ~/.claude/redline, outside the plugin, so updates never touch them.

Hacking on Redline itself? Install from a git clone instead

Use one or the other, not both, or the skills load twice.

$ git clone https://github.com/NikkyAmresh/redline ~/.claude/redline
$ for s in redline plan-review prototype-review; do ln -s ../redline/skills/$s ~/.claude/skills/$s; done
$ sh ~/.claude/redline/skills/redline/redline.sh start
